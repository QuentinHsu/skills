## Maintenance Conventions

### General

- `README.md` keeps install/update guidance and links to this index.
- Skill details belong in each skill's own files (`SKILL.md`, `rules/*.md`, `_shared/*.md`).
- Frontmatter contains only `name`, `description`, and `metadata.{author, version}`. `metadata.version` uses `YYYY.MM.DD`.
- `description` states what the skill does, when to use it, and a few representative trigger phrases in English and Chinese.
- Run `node scripts/lint-skills.mjs --write` and `node scripts/sync-shared.mjs` after adding, renaming, or editing skills. CI runs both in check mode.

### Shared Files

- `skills/<group>/_shared/` is the single source of truth.
- `scripts/sync-shared.mjs` copies into each skill's `_shared/` only the files that its `SKILL.md` references, so single-skill installs keep working links. Never edit the copies directly.

### Git Change Writing

- Diff-driven skills (`branch-name`, `pr-content`, `change-pack`) compare the **current branch against the base branch** (user-specified base first, then `main`, then `master`).
- Include uncommitted changes only when explicitly requested.
- `commit-message` stays staged-first by design (`git diff --cached`).

### Frontend

- `frontend-code-style` targets TypeScript, TSX, and DOM markup. Apply rules in order: TS, then TSX, then DOM accessibility.
- Style rules focus on readability and correctness, not formatting. Formatting belongs to the formatter.

### Privacy

- `data-sanitization` treats local real data as sensitive by default. Anything that may be uploaded, shared, pasted into external services, or included in remote prompts must be sanitized first.

### Refactor

- Refactor skills (`clean`, `migrate`, `modernize`, `architecture`) are scoped by change type. Do not mix concerns across skills in a single pass.
- All refactor skills must preserve behavior. Warn the user before proceeding when the target code has no test coverage.

### Docs

- `readme-public-app` produces polished README files with centered headers, badges, and feature showcases.
- Output is bilingual (English + Chinese) by default. Use a single language only when explicitly requested.
- When updating an existing README, keep accurate content and the user's custom sections.
